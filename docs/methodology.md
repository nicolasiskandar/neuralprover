# Research design and methodology

## Research question and hypotheses

Primary question: under equal model inference, Lean execution, and wall-clock budgets, does LoRA adaptation plus best-first search solve more held-out Lean theorems than the unadapted model with greedy decoding? Secondary question: do state deduplication and search priority improve efficiency?

H1: task fine-tuning improves held-out tactic prediction and verified solve rate. H2: bounded best-first search improves verified solve rate over greedy decoding at equal budgets. H3: safe deduplication reduces Lean work without reducing solve rate. These are hypotheses, not established conclusions.

## Baselines, measures, and controls

Planned comparisons: base+greedy, base+bounded search, LoRA+greedy, LoRA+best-first, LoRA+best-first+dedup. Hold model revision, theorem split, decoding samples, per-theorem generation allowance, Lean timeout, and wall-clock budget fixed. Record attempted/verified counts, pass@1 and pass@10 with the sampling protocol, solve-time distribution, tactic calls, expanded nodes, generated tokens, invalid/timeout rates, and hardware use. Use paired bootstrap or binomial confidence intervals for solve rates once sample sizes permit. Tactic exact match is a diagnostic only: alternative valid tactics lower exact match, while matching a tactic does not establish proof completion.

## Established methods and possible contribution

LeanDojo/ReProver establish theorem/goal extraction, tactic generation, and retrieval-augmented proving as prior art. LoRA is an established parameter-efficient adaptation technique. Best-first search and deduplication are also established algorithmic patterns. A defensible contribution would therefore be a careful, controlled study of a resource-aware search policy or state-prioritization method on a declared Lean benchmark—not the mere combination of these components. The current work has not established a novel improvement.

## Data and limitations

The checked-in pilot includes two local Lean core examples and one Mathlib-backed replay example (`Nat.div_right_comm`). Its source imports and active namespace/open/variable context are reconstructed without importing the target theorem, and the tactic passes Lean replay and kernel verification. The pilot is only an integration fixture. The parser supports simple one-tactic declarations and reports unsupported blocks. File-level hashing assigns the one Mathlib row to train; it cannot populate disjoint validation/test sets. Theorem/proof similarity audits beyond duplicate source declaration IDs remain outstanding.

The pinned Lean frontend has a native InfoTree exporter (`neuralproof data trace`) and a conservative normalizer (`neuralproof data normalize-trace`). The latter chooses source-backed tactic spans, groups wrapper/macro duplicates, and associates declaration-less nodes only when their source range lies inside a unique named proof. It constructs context from module imports and active scope directives and retains explicit provenance. On pinned `Mathlib/Data/Nat/Basic.lean`, tracing emitted 1,463 raw nodes; normalization kept 40 source tactic transitions and excluded the rest as wrappers/non-parser nodes or span duplicates. The original file elaborated successfully, but the reconstructed contexts have not all been replayed independently. Those examples are trajectory-supervision candidates, not standalone theorem proof certificates; the existing narrow replay extractor remains the verified-row path.

The resumable native extractor (`neuralproof data trace-corpus --files 200`) completed the first 200 sorted Mathlib paths at revision `56a005855ea17e0b0958f73ec801ae140b0a1679` (file-list SHA-256 `f487dddd67ed7022875985f479aabccb46307660ec4c3b7ae3f2c414a67a2e2c`). It produced 6,221 tactic transitions across 176 files: 4,977 train, 798 validation, and 446 test. The file-level split contains 139 train, 15 validation, and 22 test files among files with examples. No fully qualified source declaration name crossed splits, there were zero duplicate example IDs and broad imports, and 199/200 source files elaborated through the tracer. `Mathlib/Algebra/Category/ModuleCat/Monoidal/Adjunction.lean` failed because the frontend hit the file's heartbeat limit, followed by elaboration errors; it is recorded in `file_stats.jsonl` and `summary.json`. The split is file-level but confined to the first sorted 200 paths (mostly Algebra and Category), so it does not represent all Mathlib domains. Further, successful whole-file elaboration establishes that the original tactic trajectories occurred in a valid Lean environment; it does not establish that reconstructed contexts alone replay. Use the data for next-tactic prediction with this caveat; theorem-solving evaluation should use the independently replay-verified corpus or add a validation/replay stage first.

The first 200-file corpus draft used `import Mathlib` in every replay context. An audit found this could import the theorem being mined; that 93-row corpus was discarded and replaced. The current clean run uses source imports plus active namespace/open/variable/local directives and does not include the target declaration. On the same deterministic sorted prefix (file-list SHA-256 `f487dddd67ed7022875985f479aabccb46307660ec4c3b7ae3f2c414a67a2e2c`), it processed all 200 files and returned 25 verified records across 11 files: 22 train, 1 validation, and 2 test. Split file counts are 9, 1, and 1; there are no repeated source declaration IDs and the corpus audit found zero broad `import Mathlib` contexts. It saw 3,059 theorem/lemma headers, recognized 262 supported simple headers, and recorded 237 selected candidate failures (104 multi-tactic bodies, 76 replay failures, 32 goal-inspection failures, 25 final verification failures). Earlier declarations in the same source file are not reconstructed, so failures may be missing-context cases. These figures characterize the parser's supported subset, not Mathlib extraction coverage. It checks one-line `:= by` headers and one-line tactic bodies, not arbitrary Lean syntax. File-level source hashing reduces within-file leakage but related lemmas across files may still cross splits. Detailed per-file counts are in `data/mathlib-200/summary.json` and `file_stats.jsonl`; prompt-formatted training files are in `data/mathlib-200/processed/`.

## Experimental status

An oracle static candidate list containing the three Nat source tactics solved those three mined examples under width-three/20-node search: 3/3 verified, one node expanded and two tactic executions per theorem on average, about 10.54 seconds per theorem, Wilson 95% interval [0.438, 1.000]. Since the correct source tactics were supplied as candidates, this only validates extraction-to-search-to-kernel integration. The two examples from separate modules were individually replayed and kernel-verified during extraction but are not included in that search result. The earlier local core smoke run was 2/2 with interval [0.342, 1.000].

A CPU training run used the clean 22-row train split with the pinned SmolLM2-135M base (Python 3.11.17, PyTorch 2.6.0+cpu, Transformers 4.49.0, PEFT 0.14.0, seed 17, one epoch, 22 steps). Training loss was 4.4752; no validation metric was computed. On the same two held-out test rows with a 6-node/width-3 bounded search, the base model and LoRA adapter each verified 0/2 (Wilson 95% interval [0, 0.658]); pass@10 was not measured. The adapter expanded 1.5 nodes and made 4.5 tactic executions per problem on average, versus 1.0 node and 3.0 calls for the base. All attempted tactics were invalid (6 base, 8 LoRA total), and GPU metrics were unavailable. With only two test theorems this is a smoke check, not a model comparison supporting the research hypothesis. Outputs are under `experiments/clean-base-test/` and `experiments/clean-lora-test/`. The earlier five-row run used a superseded broad-import dataset and remains historical debugging only.

The InfoTree corpus was preprocessed with the shared context+goal prompt and trained for 100 steps on CPU (5,000-step full epoch was estimated near two hours and stopped before checkpointing). The 100-step checkpoint's training loss was 4.6356 after 142.4 seconds. `neuralproof evaluate-tactics` then compared greedy top-1 base vs LoRA prediction on the same deterministic 50 of 446 held-out test examples, limited to single-line source tactics. Both were 0/50 exact matches (Wilson 95% interval [0, 0.07135]); inference took 114.8 seconds for base and 145.6 seconds for LoRA. This negative pilot does not support the fine-tuning hypothesis. It does show that the current small adaptation budget and base model are not yet producing the source tactic labels. It is a tactic prediction metric, not a proof success metric; the normalized contexts have not been independently replayed.
